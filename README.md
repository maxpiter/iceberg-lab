# Iceberg Lab: Apache Iceberg вместе с системой прав

Учебный стенд, который поднимается одной командой. На нём можно руками попробовать, как устроены таблицы Apache Iceberg и как на них раздаются права: кто какие таблицы видит, кто может писать, где хранится разрешение и где видно отказ.

Пользователь работает только с Trino, обычным SQL из DBeaver или веб-интерфейса. Всё остальное (каталог, права, хранилище файлов) скрыто за Trino, и на стенде видно, как оно отвечает на каждый запрос.

> Все пароли и секреты в этом репозитории учебные и опубликованы. Стенд предназначен только для локальных опытов на своём компьютере.

## Из чего состоит стенд

| Компонент | Что делает |
|---|---|
| Trino | SQL-движок. Единственная точка входа для пользователя |
| nginx | даёт Trino HTTPS, без него вход через Keycloak не работает |
| Keycloak | вход пользователей и технических учёток |
| OPA | перед каждым действием Trino спрашивает у него, можно ли |
| Lakekeeper | каталог Iceberg: знает, какие есть таблицы, где лежат их файлы и кому что можно |
| OpenFGA | хранит права, которые раздаются в Lakekeeper |
| RustFS | хранилище S3, где физически лежат файлы таблиц |
| PostgreSQL (2 шт.) | служебные базы Lakekeeper и OpenFGA |

## Требования

- Docker с Compose v2 (команда `docker compose`). На Windows и macOS подойдёт Docker Desktop.
- Не меньше 8 ГБ оперативной памяти на машине, сам стенд в покое занимает около 2,5 ГБ.
- Свободные порты на 127.0.0.1: `8181`, `8443`, `9100`, `9101`, `30080`.
- Браузер Chrome, Edge или Firefox (для предпросмотра данных в UI Lakekeeper).

## Запуск

```bash
git clone https://github.com/maxpiter/iceberg-lab.git
cd iceberg-lab
docker compose up -d
```

Первый запуск занимает несколько минут: скачиваются образы, Keycloak импортирует настройки, каталог настраивается. Стенд готов, когда команда

```bash
docker compose ps
```

показывает у `trino-proxy` состояние `healthy`. Служебные задания (`secrets-init`, `create-bucket`, `openfga-migrate`, `migrate`, `lk-init`) должны быть в состоянии `exited` с кодом `0` - они отработали один раз и завершились, так и задумано.

После запуска в каталоге есть только пустой warehouse `demo`: ни схем, ни таблиц. В UI Lakekeeper поначалу смотреть не на что, первая таблица создаётся в главе [02-first-table.md](docs/02-first-table.md) после подключения DBeaver.

Если Docker работает на другой машине (например, на сервере, к которому вы подключаетесь через VS Code Remote SSH), пробросьте на свой компьютер все пять портов из требований. В VS Code это вкладка Ports.

## Адреса и учётные записи

### Веб-интерфейсы

| Система | Адрес | Логин / пароль | Что там смотреть |
|---|---|---|---|
| Lakekeeper | http://localhost:8181/ui | `engineer` / `engineer` или `analyst` / `analyst` (вход через Keycloak) | warehouse `demo`, схемы и таблицы, выдача прав, предпросмотр данных |
| Trino | https://localhost:8443/ui/ | `engineer` или `analyst` (вход через Keycloak) | история запросов, кто и что выполнял |
| RustFS (S3) | http://localhost:9101 | `rustfsadmin` / `rustfs-lab-secret` | бакет `warehouse`, папка `demo`: файлы Parquet и метаданные таблиц |
| Keycloak, администрирование | http://localhost:30080/admin | `admin` / `admin` | после входа слева вверху выберите realm `iceberg`: там пользователи и клиенты стенда |
| Keycloak, кабинет пользователя | http://localhost:30080/realms/iceberg/account | `engineer` / `engineer` или `analyst` / `analyst` | выход из сессии, когда нужно сменить пользователя |

У Trino самоподписанный сертификат, поэтому браузер покажет предупреждение о небезопасном соединении. Для учебного стенда это нормально: нажмите "Дополнительно" и "Перейти на сайт".

У OpenFGA и OPA веб-интерфейса нет, они работают внутри сети стенда. Их работу видно по выдаче прав в UI Lakekeeper и по отказам в Trino.

### Подключение DBeaver к Trino

Главный способ работы со стендом. **Подробная инструкция по шагам, с объяснением каждого параметра, сменой пользователя и разбором ошибок - [docs/01-dbeaver.md](docs/01-dbeaver.md).**

Коротко: драйвер Trino, `localhost:8443`, база `lakekeeper`, Username и Password **пустые**, в Driver properties `SSL=true`, `SSLVerification=NONE`, `externalAuthentication=true`, `externalAuthenticationTokenCache=MEMORY`. Логин и пароль вводятся в браузере на странице Keycloak, которую DBeaver откроет сам. Нужны порты `8443` и `30080`.

### Пользователи стенда

| Логин / пароль | Роль | Права после запуска |
|---|---|---|
| `engineer` / `engineer` | инженер данных | администратор каталога: создаёт схемы и таблицы, раздаёт права |
| `analyst` / `analyst` | аналитик | никаких. Права ему выдаёт engineer по ходу сценария |

### Технические учётки (клиенты Keycloak)

Под ними ходят программы, а не люди. Секреты лежат в `keycloak/realm.json`.

| Клиент | Кто под ним работает | Права в каталоге |
|---|---|---|
| `trino` | Trino и OPA | администратор проекта. Права конкретного пользователя Trino проверяет через OPA |
| `loader` | пример для вашего загрузчика данных (Spark, Flink, Kafka Connect, SeaTunnel и т.п.) | создание и запись в warehouse `demo` |
| `spark` | первичная настройка каталога (имя осталось из официального примера Lakekeeper) | администратор сервера |
| `openfga` | Lakekeeper при обращении к OpenFGA | - |

## Сценарии

Главы идут по порядку, каждая опирается на предыдущую:

1. [Подключение DBeaver к Trino](docs/01-dbeaver.md) - вход через Keycloak, смена пользователя, типичные ошибки.

## Ограничения

Что в стенде упрощено ради учёбы и что нужно решить до рабочей системы (учётка Trino, маски данных, группы AD, каталоги вне Lakekeeper, TLS и секреты) - в [docs/06-limitations.md](docs/06-limitations.md).

## Остановка и сброс

```bash
docker compose stop        # остановить, данные сохранятся
docker compose start       # запустить снова
docker compose down -v     # удалить стенд вместе со всеми данными и начать с нуля
```
