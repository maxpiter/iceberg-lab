# Подключение DBeaver к Trino

Это главный способ работы со стендом. Аналитик или инженер открывает DBeaver, подключается к Trino и пишет обычный SQL. Каталог, права и файлы в S3 остаются за Trino, пользователь их напрямую не трогает.

Отличие от привычного подключения к базе данных одно: логин и пароль вводятся не в DBeaver, а в окне браузера на странице Keycloak. Так устроен вход в большинстве компаний с единой учётной записью (SSO), и стенд повторяет эту схему.

## Что должно быть готово

1. Стенд запущен, `docker compose ps` показывает `trino-proxy` в состоянии `healthy`.
2. На вашем компьютере открываются два порта:
   - `8443` - Trino (через nginx с HTTPS);
   - `30080` - Keycloak, на нём откроется страница входа.

   Если Docker работает на этом же компьютере, ничего делать не нужно. Если на сервере (например, вы подключены к нему через VS Code Remote SSH), пробросьте оба порта: в VS Code вкладка Ports, кнопка Forward a Port. Проверьте, что в колонке Local Address стоят те же номера `8443` и `30080`. Если VS Code пробросил на другой порт, потому что этот у вас занят, вход не заработает: адрес возврата после входа привязан к этим номерам.
3. Установлен DBeaver (подойдёт бесплатный Community Edition).

Быстрая проверка: откройте в браузере `http://localhost:30080/realms/iceberg`. Должна появиться короткая служебная страница в формате JSON. Если браузер пишет, что не может открыть страницу, порт 30080 не проброшен.

## Шаг 1. Создать подключение

1. В DBeaver выберите меню Database, пункт New Database Connection.
2. В списке баз найдите **Trino** (удобно набрать название в строке поиска) и нажмите Next.
3. Если DBeaver предложит скачать драйвер, согласитесь. Это нужно один раз.

## Шаг 2. Вкладка Main

| Поле | Значение | Пояснение |
|---|---|---|
| Host | `localhost` | |
| Port | `8443` | порт nginx, который отдаёт Trino по HTTPS |
| Database | `lakekeeper` | каталог Trino, в котором лежат таблицы Iceberg |
| Username | **оставить пустым** | см. ниже |
| Password | **оставить пустым** | |

Почему Username пустой. Пользователя Trino узнаёт из токена Keycloak после входа в браузере. Если в DBeaver заполнить имя, Trino воспримет это как просьбу выполнять запросы от имени другого пользователя (impersonation). Политика прав такое запрещает, и подключение получит отказ.

## Шаг 3. Вкладка Driver properties

На этой вкладке список свойств драйвера. Нужные свойства часто уже есть в списке, тогда достаточно вписать значение. Если какого-то нет, щёлкните правой кнопкой по списку и выберите Add new property.

| Свойство | Значение | Зачем |
|---|---|---|
| `SSL` | `true` | Trino принимает вход через Keycloak только по HTTPS |
| `SSLVerification` | `NONE` | у стенда самоподписанный сертификат, без этого драйвер откажется ему доверять. В рабочей системе здесь будет корпоративный сертификат и проверка останется включённой |
| `externalAuthentication` | `true` | включает вход через браузер |
| `externalAuthenticationTokenCache` | `MEMORY` | DBeaver запоминает токен на время работы и не открывает браузер на каждый новый запрос или окно |

Нажмите Finish.

## Шаг 4. Подключиться и войти

1. Дважды щёлкните по новому подключению или нажмите Connect.
2. DBeaver сам откроет браузер со страницей входа Keycloak (realm `iceberg`).
3. Введите `engineer` / `engineer`.
4. Браузер покажет сообщение, что вход выполнен. Вкладку можно закрыть и вернуться в DBeaver.

В дереве подключения появится каталог `lakekeeper`, а в нём схемы и таблицы, на которые у вас есть права. Каталог `tpch` с тестовыми данными в дереве может не показываться, но запросы к нему работают.

## Что происходит при подключении

```
DBeaver --HTTPS--> nginx :8443 --> Trino
                                     |
                      "кто это?"     |  Trino отправляет DBeaver ссылку на вход
                                     v
             браузер --> Keycloak :30080 (логин и пароль)
                                     |
                                     v
                       токен пользователя --> DBeaver --> Trino
```

Дальше на каждый запрос:

```
Trino --"можно ли engineer читать sales.orders?"--> OPA --> Lakekeeper --> OpenFGA
Trino <-- адрес файлов и временный ключ к S3 ------- Lakekeeper
Trino --читает Parquet--> RustFS (S3)
```

Trino проверяет права пользователя через OPA, а OPA спрашивает Lakekeeper, где хранятся разрешения. Файлы таблицы Trino читает из S3 сам по временному ключу, который выдал каталог.

## Шаг 5. Проверить подключение

Проверить, под кем вы вошли:

```sql
SELECT current_user;
```

Вернётся длинный идентификатор вида `cfb55bf6-...`. Это идентификатор пользователя в Keycloak, и под ним же пользователь известен каталогу Lakekeeper.

Тестовые данные: в Trino встроен каталог `tpch`, который генерирует таблицы на лету. Ничего скачивать не нужно:

```sql
SELECT count(*) FROM tpch.tiny.orders;
```

Если оба запроса отработали, подключение настроено. Каталог `lakekeeper` пока пустой: первая таблица Iceberg создаётся в следующей главе, [02-first-table.md](02-first-table.md).

## Как сменить пользователя

DBeaver и браузер запоминают вход, поэтому простое переподключение вернёт вас под тем же пользователем. Чтобы войти как `analyst`:

1. В DBeaver нажмите Disconnect и **полностью закройте DBeaver**. Токен хранится в памяти драйвера, и он общий для всех подключений в одном запущенном DBeaver, так что второе подключение к тому же Trino не поможет.
2. В **браузере по умолчанию** (том, который открывает DBeaver при входе) откройте
   `http://localhost:30080/realms/iceberg/protocol/openid-connect/logout`
   и нажмите Logout. Без этого Keycloak узнает вас по сессии в браузере и впустит под прежним пользователем, не показав форму входа. Выход нужно делать именно в браузере по умолчанию: если DBeaver открывает Edge, а выход сделан в Chrome, сессия в Edge останется.
3. Запустите DBeaver, подключитесь и введите `analyst` / `analyst`.

Если Keycloak всё равно пускает без формы входа, закройте сессии на стороне Keycloak, это работает независимо от браузера:

1. откройте http://localhost:30080/admin, войдите `admin` / `admin`;
2. слева вверху выберите realm `iceberg`;
3. в меню Sessions нажмите Sign out all active sessions.

После этого все пользователи стенда разлогинены, и при следующем подключении Keycloak спросит логин и пароль.

Сразу после запуска стенда у analyst нет никаких прав, и любой запрос к `lakekeeper` получит отказ. Права ему выдаёт engineer в UI Lakekeeper.

Если переключаться приходится часто, поставьте `externalAuthenticationTokenCache` = `NONE`. Тогда DBeaver не будет держать токен, но браузер для входа будет открываться чаще.

## Если не получается

| Что видите | Причина | Что сделать |
|---|---|---|
| Браузер не открылся после Connect | DBeaver не нашёл браузер по умолчанию | проверьте, что в системе задан браузер по умолчанию; ссылку на вход можно найти в журнале ошибок DBeaver и открыть вручную |
| Браузер открылся, но страница не загружается (`localhost:30080`) | не проброшен порт 30080 | пробросьте порт, см. "Что должно быть готово" |
| После входа браузер пишет, что не может открыть `localhost:8443` | не проброшен порт 8443 или проброшен под другим номером | пробросьте именно 8443 |
| Ошибка про сертификат, `PKIX path building failed` | не задан `SSLVerification` | `SSLVerification` = `NONE` на вкладке Driver properties |
| Ошибка со словами `impersonate` или `Access Denied` сразу при подключении | заполнено поле Username | очистите Username и Password на вкладке Main |
| `Access Denied: Cannot access catalog lakekeeper` | у пользователя нет прав ни на одну таблицу каталога | для analyst это ожидаемо, пока engineer не выдал права |
| `Access Denied: Cannot insert into table ...` | есть право на чтение, но не на запись | так и должно быть, права раздаются по отдельности |
| Подключились не под тем пользователем, форма входа не появляется | вход запомнили DBeaver или Keycloak в браузере по умолчанию | см. "Как сменить пользователя" |
| `Connection refused` на 8443 | стенд ещё не поднялся | дождитесь `healthy` у `trino-proxy` в `docker compose ps` |
