# Ограничения стенда и что нужно до рабочей системы

Стенд собран, чтобы руками попробовать Iceberg вместе с правами доступа. Часть решений в нём учебная, часть отражает реальные ограничения связки Lakekeeper + OpenFGA + Trino на сегодня. Ниже и то, и другое, чтобы было понятно, что переносить в компанию как есть, а что придётся решать.

## Учётка trino видит всё

Trino ходит в каталог одной технической учёткой `trino` с правами администратора проекта. Права конкретного пользователя Trino проверяет сам: перед каждым действием спрашивает OPA, а OPA спрашивает Lakekeeper от имени этого пользователя. Lakekeeper называет такую схему "trusted query engine" - движку доверяют, что он добросовестно спросит.

Отсюда следует, что секрет клиента `trino` равен паролю администратора каталога. Кто его знает, тот читает и меняет любые таблицы в обход OPA.

Передавать каталогу токен самого пользователя Trino пока не умеет. Изменение предложено в [trinodb/trino#29758](https://github.com/trinodb/trino/pull/29758); если его примут, права сможет проверять сам каталог.

## Права заканчиваются на таблице

В OpenFGA права выдаются на warehouse, схему, таблицу или представление. Маскировать колонки (паспорт, номер карты) и фильтровать строки (только свой филиал) Lakekeeper не умеет. Это делает движок: в Trino такие правила пишутся в OPA или в файловом контроле доступа Trino, отдельно от прав в OpenFGA.

Есть важное следствие. Право `select` в каталоге одно на все способы чтения. С ним человек может прийти в Lakekeeper напрямую (через Spark, DuckDB или тот же UI Lakekeeper с предпросмотром) и прочитать таблицу без масок Trino. Если маски нужны, Lakekeeper и S3 закрываются от пользователей сетью, и в данные ходит только Trino.

## Каталоги вне Lakekeeper открыты всем

Мост OPA от Lakekeeper проверяет права только для каталогов Trino, привязанных к warehouse Lakekeeper. Для остальных у него два режима: всё запрещено или всё разрешено. В стенде включено "всё разрешено" (`TRINO_ALLOW_UNMANAGED_CATALOGS=true` в `docker-compose.yml`), потому что такой каталог один - `tpch` с тестовыми данными только для чтения.

Если вы добавите в `trino/catalog` свой источник, например PostgreSQL, он тоже станет доступен всем вошедшим. Закрыть его можно тремя способами:

1. **Файловый контроль доступа Trino** вторым модулем рядом с OPA (`access-control.config-files`). Trino пропускает запрос, только если ни один модуль не отказал. Правила пишутся в JSON по пользователям и группам: на каталог `all`, `read-only` или `none`, на таблицы отдельные привилегии, там же маски колонок и фильтры строк. См. [File-based access control](https://trino.io/docs/current/security/file-system-access-control.html).
2. **Свои правила в OPA.** Мост предусматривает для этого файл `opa/policies/trino/allow_unmanaged.rego`.
3. **Права в самом источнике.** Trino подключается к базе одной учёткой, и все пользователи Trino получают её права.

В любом варианте права на таблицы Iceberg хранятся в OpenFGA, а на остальные источники - в другом месте.

## Пользователь Trino - это UUID, а не логин

Trino берёт имя пользователя из поля `sub` токена Keycloak. Поэтому `SELECT current_user` возвращает идентификатор вида `cfb55bf6-...`, и в истории запросов Trino видны такие же идентификаторы. Мост OPA сопоставляет пользователя с Lakekeeper как `oidc~<пользователь Trino>`, и это работает, только пока имя в Trino равно `sub`.

Это мешает группам из Active Directory. Trino умеет брать группы из LDAP (поставщик групп `ldap`, см. [Group mapping](https://trino.io/docs/current/security/group-mapping.html)), но ищет в каталоге пользователя по имени Trino и по UUID никого не найдёт. Чтобы в Trino были логины, нужно поменять `http-server.authentication.oauth2.principal-field` и вслед за ним сопоставление в `opa/policies/trino/user.rego`.

## Группы AD в Lakekeeper с OpenFGA

В открытой версии Lakekeeper с OpenFGA роли хранятся в самом OpenFGA, а группы из LDAP или Entra ID через role providers использует только авторизатор Cedar. Роли из токена (`LAKEKEEPER__OPENID_ROLES_CLAIM`) OpenFGA тоже не читает. Синхронизацию групп AD с ролями Lakekeeper придётся делать своим скриптом через management API.

Ещё одна деталь: без такого скрипта пользователь появляется в Lakekeeper только после первого входа, до этого выдать ему права в UI нельзя. Заводить пользователей заранее можно через `POST /management/v1/user` с их идентификатором, так делает `init/lk-init.sh` для engineer и analyst.

## Владельцы раздают права сами

Кто создал схему или таблицу напрямую через каталог (UI Lakekeeper, Spark, загрузчик), становится её владельцем и может сам выдавать на неё права в UI Lakekeeper. С регламентом "доступ только по заявке" это расходится. В Lakekeeper для этого есть режим Managed Access: на warehouse или схеме он отбирает у владельцев право раздачи.

Через Trino картина другая: владельцем всех созданных таблиц становится техническая учётка `trino`, потому что в каталог Trino ходит под ней. Пользователь, выполнивший `CREATE TABLE` в DBeaver, владельцем не становится, и права на таблицу раздаёт администратор.

## Каталог - точка отказа

Каждый запрос Trino проходит через OPA и Lakekeeper. Если Lakekeeper недоступен, Trino отказывает всем. Для безопасности это правильно, но для рабочей системы каталог, OpenFGA, Keycloak и их базы нужно резервировать.

## Учебные упрощения стенда

Это сделано ради простоты запуска и в рабочую систему не переносится:

| В стенде | В рабочей системе |
|---|---|
| Пароли и секреты клиентов лежат в репозитории | свои секреты, хранилище секретов (например, Vault) |
| HTTP у Lakekeeper, Keycloak, RustFS | TLS на всех сервисах |
| Самоподписанный сертификат nginx, в DBeaver `SSLVerification=NONE` | корпоративный сертификат, проверка включена |
| Keycloak в режиме `start-dev` со встроенной базой | режим `start` со своей PostgreSQL |
| Lakekeeper ходит в S3 под root-ключом RustFS | отдельный пользователь S3 с политикой на один бакет |
| `min-retention=0s` для `expire_snapshots` и `remove_orphan_files` в `trino/catalog/lakekeeper.properties` | значения по умолчанию (7 дней): с нулём можно удалить файлы записи, которая ещё идёт |
| Все сервисы в одном docker compose без резервирования | резервирование и резервные копии Keycloak, OpenFGA, Lakekeeper и их баз |
